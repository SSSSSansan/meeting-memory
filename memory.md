- [2026-11-04][C][C1] Чанк baseline = окно из 3 реплик со сдвигом 2 (одна реплика в двух соседних чанках); реплики длиннее 80 слов режутся по предложениям. В чанке `meeting_id`, `date`, `title`, склеенный `text` «[ts] speaker: текст» и `segments` с `ts/speaker/text/start_s` для точной цитаты. Индекс — numpy-матрица нормированных векторов в `runs/index/baseline/`, хранит backend и `EMBED_MODEL` и не грузится под другой моделью. Почему: реплика-ответ без предыдущей теряет смысл; ASR без диаризации даёт реплики до ~190 слов. Влияет на: C (C2/C3 цитаты), A (параметры чанка — в заголовок результатов eval).
- [2026-11-04][C][C2] Ответ: `src.answer.answerer.answer(question, mode="baseline", k=5)` → `Answer` (4.6). Промпт 11.3 в `src/answer/prompts.py`, общий для baseline и graph; graph-ветка зовёт `generate(question, context, mode)` со своим контекстом. Контекст: встречи по дате, реплики по времени без повторов, каждая строка с меткой `[meeting_id ts]`. Пустой поиск → «В контексте нет информации…» без вызова LLM; не-JSON от модели → текст без цитат. `latency_ms` включает поиск, `usage` — пока только токены LLM, эмбеддинги не считаются. Влияет на: A (eval зовёт `answer()`), C (C3 проверка цитат, C4/C5).
- [2026-11-04][C][C3] Цитата ответа валидна, если после `normalize` (кавычки «» по краям срезаются) она подстрока строки контекста с той же меткой `[meeting_id ts]`. Верная цитата с чужой меткой переносится на строку, только если такая строка одна. Иначе — 1 ретрай с перечнем плохих цитат (без текста ошибки ретрай вернулся бы из кэша), потом плохие выбрасываются, а в ответ дописывается «Удалено неподтверждённых цитат: N». Статистика по каждому вопросу — `runs/answer_report.jsonl`: `citations_first`, `invalid_first` (доля невалидных цитат = Σinvalid_first / Σcitations_first), `relocated`, `dropped_final`, токены. Graph-контекст (C4) обязан использовать тот же формат строк, иначе все цитаты будут отклонены. Влияет на: A (метрика citation correctness / hallucination ответов), C (C4).
- [2026-11-04][C][C6,P8] UI ходит только в `src/api.py`: `pair_scribal_files` (пара `<id>.transcript.json` + `<id>.meeting.json`, как в `data/raw/`), `load_scribal` (через адаптер роли B), `index_batches` (по 5 встреч, индекс сохраняется после каждого батча в `runs/index/baseline/`, повтор не дублирует), `indexed_meetings`, `reset_index`, `ask`. Кнопка «Демо-встречи» индексирует `data/raw/`. Почему: правило «UI без логики», eval и демо используют одни функции. Влияет на: A (eval может звать `api.ask`), C (C7).
- [2026-11-04][C][P1,P2] `llm_client`: сетевые сбои/429/5xx повторяет клиент openai (`LLM_MAX_RETRIES`=3, `LLM_TIMEOUT_S`=120); `embed()` для openai/local теперь проходит `cost_guard` и пишется в `runs/calls.jsonl` (`kind=embed`, `purpose=embed_index|embed_query`, цена — `PRICE_EMBED_PER_M`). В логе у каждой строки `backend`, `purpose`, `kind`, `from_cache`; ответы из кэша тоже логируются, реальные траты — поле `spent_usd` (у кэша 0), `cost_usd` — цена ответа для сравнения режимов. Влияет на: A (отчёт о стоимости суммирует `spent_usd`, стадии — по `purpose`), B (extract логируется так же).
- [2026-11-04][C][C4] GraphRAG: `retrieve_subgraph(question, depth=2)` в `src/retrieval/graph_rag.py`. Сущности — проекты (все слова названия) и люди (одно слово имени) по совпадению основы: «Атласу» → «Атлас». Обход BFS на `depth` шагов по BELONGS_TO/ASSIGNED_TO/IMPLEMENTS и связям решений; через встречи, чужие проекты и людей не ходит. Для человека добавляются пункты, где он назван в тексте. «последние N встреч» фильтрует по встречам проекта. Без сущностей — запасной режим: до 40 пунктов, сначала конфликты. Контекст: по проектам, внутри — по дате, со статусами, связями и rationale; источник — строка `[meeting_id ts] цитата: <quote узла>`, поэтому цитата ответа должна быть из `quote`, а не из «Сути». `answer(..., mode="graph")` и `api.ask(mode="graph")` работают. Граф читается из `data/graph/graph.json`, пока его нет — `data/sample/graph.json` (старый сюжет Атлас/Горизонт). Влияет на: B (сущности матчатся по `label` узлов — после resolve должны быть канонические имена), A (depth — в заголовок результатов eval), C (C5 роутер).
