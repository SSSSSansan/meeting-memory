# Память встреч: baseline RAG против GraphRAG — отчёт (черновик)

Статус: черновик от 14 ноября 2026, до прогона test. Разделы с **TODO** ждут данных; цифры без ссылки на файл не приводятся. Сводка всех расчётных цифр: [results/report_numbers.md](results/report_numbers.md) (`python scripts/report_numbers.py`, без вызова модели).

## 1. Задача и гипотеза

Задача Scribal: отвечать на вопросы по истории встреч (что решили, как менялось решение, кто на что назначен, что осталось открытым) с цитатой и таймкодом. Сравниваем обычный поиск по фрагментам (baseline RAG) и поиск по графу решений (GraphRAG) по типам вопросов T1–T5, со стоимостью и задержкой. Отрицательный результат по графу считается результатом.

Гипотеза записана до открытия test: [docs/hypothesis_2026-11-14.md](docs/hypothesis_2026-11-14.md) (7 пунктов). Итог по каждому пункту — в разделе 5 после прогона test, формулировки не меняются.

## 2. Данные

Набор синтетический: тексты встреч написаны Gemini по сюжету [data/gold/world.yaml](data/gold/world.yaml), вычитаны вручную, шум ASR (искажения слов и меток говорящих, нарезка) добавлен скриптом `scripts/add_noise.py` (зерно 42). Формат входа — Scribal JSON ([data/raw/](data/raw/)).

- **14 встреч** (m_001–m_013 и m_015; m_014 исключена из-за нехватки времени, номера не менялись), 3 августа – 26 октября 2026, **4 проекта** (Zhol, Squad, Qamqor, Boost), 7 людей. Профили языка: ru 10, mixed 2, kk 2 ([world.yaml](data/gold/world.yaml)).
- Объём: 1505 реплик, 15 743 слова, ≈112,6 мин по скорости 2,33 слова/с при плане 227 мин; в среднем ≈8 мин на встречу ([results/report_numbers.md](results/report_numbers.md), раздел 4).
- Эталон: **37 событий** ([data/gold/decisions.json](data/gold/decisions.json)), 9 связей между решениями и 6 закрытий задач в world.yaml.
- Вопросов **58**: dev 35, test 23; T1 11, T2 12, T3 9, T4 8, T5 11, без ответа в данных 7; казахских 9 (dev 6, test 3) ([data/gold/questions.json](data/gold/questions.json)).
- Доля встреч с казахской речью зависит от порога ([results/language_share.md](results/language_share.md)): при пороге 10% — 8 из 14 (57,1%), при 20% — 4 из 14 (28,6%), при 30% — 3 из 14 (21,4%). Цель задания 25–30% выполняется при пороге 20%.

Заложенные ситуации ([data/gold/scenarios.md](data/gold/scenarios.md)): эволюция срока релиза (m_001 → m_006 → m_011); решение заменено новым (m_013 заменяет m_003); отмена без замены (m_008 отменяет m_001); конфликт загрузки — один человек на двух проектах в одну неделю (m_007, m_008); встреча про один проект с обсуждением другого (m_004, m_009); зависимость решений (m_009 от m_002); забытое обещание (m_003, m_007, m_015); заочное назначение; самоисправление; размышление вслух (не решение); пересказ уже принятого; смешанная и казахская речь; шум.

## 3. Метод

**Режимы.** baseline — поиск по фрагментам (эмбеддинги `text-embedding-3-small`); graph — подграф решений и связей; hybrid — контекст graph плюс ближайшие фрагменты текста; контрольные: bm25 (лексический поиск по тем же фрагментам) и long-context (все встречи до даты вопроса целиком, без поиска).

**Одинаковый вход для всех режимов:**

| Условие | Выполнено |
|---|---|
| Корпус: те же 14 встреч из `data/raw` | да |
| Имена говорящих: одна эвристика в индексе и графе | да |
| Отсечка по дате: только встречи с датой ≤ as_of_date вопроса | да (проверено, см. memory.md, A7 2026-11-14) |
| Бюджет контекста CONTEXT_K = 10 | baseline, bm25: да (10 из 10, превышений 0; `context_symmetry` в [eval_20261114_0935.json](results/eval_20261114_0935.json), [eval_20261114_1053.json](results/eval_20261114_1053.json)); graph/hybrid: **TODO**, ждёт обрезки у роли C; long-context — без бюджета по определению |
| Промпт ответа и модель (gpt-4o) | да |
| Судья: judge-facts-v1, gpt-4o, один и тот же для всех | да |

**dev/test.** dev 35 вопросов — для разбора ошибок и настройки; test 23 вопроса (q_36–q_58) — для итоговой таблицы, запускается **один раз** после заморозки кода и промптов (харнес без `--unlock-test` отказывается запускать test). В прогонах dev участвуют 34 вопроса: q_16 привязан к состоянию m_008 и идёт отдельным прогоном.

**Метрики.** fact_f1 по фактам эталона (судья отмечает, есть ли в ответе обязательные факты, и проверяет утверждения ответа); полнота поиска (`retrieval_recall`: доля нужных встреч в контексте); цитаты (`citation_recall`, `citation_precision`, `quote_validity` — цитата дословно есть в транскрипте); отказы (`abstain_rate_unanswerable` — честный отказ на вопросах без ответа, выше лучше; `false_abstain_rate` — отказ при наличии ответа, ниже лучше); запрещённые факты (`forbidden_rate`). Интервалы — парный бутстрап по вопросам, 10 000 выборок, seed 42 (`src/eval/bootstrap.py`). Температура 0, повторов нет: при температуре 0 повторы детерминированы, поэтому интервал отражает только разброс по вопросам.

## 8. Сравнение с готовыми решениями


Сравнение сделано по документации и статьям, без запуска этих систем на наших данных.

**Microsoft GraphRAG.** Индексация извлекает сущности, связи и утверждения, строит граф знаний, выделяет иерархические сообщества и генерирует по ним сводки. Глобальный поиск отвечает на вопросы по всему корпусу через сводки сообществ: каждая даёт частичный ответ, и они затем объединяются. Сильная сторона это обобщающие вопросы: по данным Microsoft, на сводках сообществ GraphRAG выигрывает у обычного RAG по полноте и разнообразию ответов примерно в 70–80% случаев. Слабая это цена индексации: модель обрабатывает каждый фрагмент текста, поэтому стоимость растёт с объёмом корпуса, а изменение документов может сделать сводки сообществ устаревшими. Извлечение графа составляет примерно 75% стоимости индексации. Удешевлённый вариант LazyGraphRAG, по оценке Microsoft, индексирует по цене обычного векторного RAG, то есть за 0,1% стоимости полного GraphRAG.

**LightRAG.** Сочетает индексацию текста через граф с двухуровневым поиском: нижний уровень ищет точную информацию о конкретных сущностях и связях, верхний охватывает более широкие темы. Новые данные добавляются инкрементально, без перестройки всего индекса. Работа опубликована в Findings of EMNLP 2025.

**LlamaIndex PropertyGraphIndex.** Граф строится набором экстракторов, которые применяются к каждому фрагменту и прикрепляют сущности и связи к узлам как метаданные. При поиске можно вернуть вместе с найденными путями исходный фрагмент текста. В качестве хранилища поддерживается в том числе Neo4j.

| Ось | Microsoft GraphRAG | LightRAG | LlamaIndex PropertyGraphIndex | Наша система |
|---|---|---|---|---|
| Что строится при индексации | сущности, связи, сообщества и их сводки | граф сущностей и связей плюс векторы | граф сущностей и связей по экстракторам | решения, задачи, открытые вопросы и связи между решениями |
| Цена индексации | высокая, LLM на каждый фрагмент и каждое сообщество | LLM на извлечение, инкрементальные обновления | LLM на извлечение | LLM на извлечение и классификацию связей (цифры: раздел 6) |
| История изменения решений | в описании не найдено | в описании не найдено | в описании не найдено | связи «заменяет», «противоречит», «зависит от», «уточняет», вычисляемый статус решения |
| Источник с таймкодом | связь с исходными фрагментами текста | связь с исходными фрагментами | исходный фрагмент по запросу | дословная цитата с таймкодом, автоматически проверяется по транскрипту |
| Отсечка «по состоянию на дату» | в описании не найдено | в описании не найдено | в описании не найдено | фильтр as_of по дате встречи во всех режимах |
| Казахский и смешанная речь | не проверяли | не проверяли | не проверяли | нормализация казахских букв, отдельный срез метрик |

**Вывод.** Готовые системы ориентированы на сущности и темы, а не на решения во времени. В их описании мы не нашли того, что нужно руководителю в задаче Scribal: что заменило что, что чему противоречит, что действует на дату, с проверяемой цитатой. Это и есть наша добавка. Цена этой добавки та же, что у всех графовых подходов: извлечение моделью на этапе индексации.

## 10. Внедрение в Scribal

- **Вход:** выгрузка Scribal (`transcript.json` + метаданные встречи) читается адаптером `src/ingest/scribal_adapter.py` без своей схемы; `speaker_names` может быть `null`, тогда работает эвристика имён (см. ограничение 3).
- **Обработка батчами по 5 встреч:** индекс и граф дополняются инкрементально, без полной пересборки (`api.index_batches`).
- **Где встраивается:** история решений по проекту перед встречей — что решили, что менялось, что осталось открытым, с цитатами и таймкодами для перехода к записи.
- **Приватность:** в текущей версии тексты встреч уходят в OpenAI (ответы, судья, эмбеддинги). Вариант — локальная модель (backend `local`); расчёт стоимости владения: Стоимость владения локальной моделью мы не замеряли: локальный запуск исключён решением команды (без GPU и Docker, чтобы результат воспроизводился за несколько минут). Оценка строится так. Через API затраты переменные и растут с нагрузкой: ответ baseline стоит около $0,005 на вопрос на gpt-4o (results/report_numbers.md), плюс разовая индексация каждой новой встречи (для графа: раздел 6). Локальная модель даёт постоянные затраты на сервер с GPU и его обслуживание, почти не зависящие от числа вопросов. Переход на локальную модель окупается, когда месячная сумма «вопросы × цена вопроса + новые встречи × цена индексации» превышает месячную стоимость сервера. Второй довод за локальный вариант это приватность: сейчас тексты встреч уходят в OpenAI, для клиентов Scribal с закрытыми встречами это может быть неприемлемо. Ограничение: качество локальных моделей на казахском и смешанной речи мы не проверяли, а от него зависит, применим ли локальный вариант для 20–30% встреч Scribal с казахской речью..
