# closures.json — эталон закрытий для оценки детекции

## Что это

Список из 6 пар «что закрыто — чем закрыто», выгруженный из раздела `closures` файла `world.yaml`
(`python scripts/export_closures.py`, повторный запуск даёт тот же файл). Поля записи:

| Поле | Значение |
|---|---|
| `task_event_id` | id закрытого события (`ev_mNNN_NN`) |
| `closing_event_id` | id события, которое его закрыло |
| `task_statement` | формулировка закрытого события из `world.yaml` |
| `closing_statement` | формулировка закрывающего события из `world.yaml` |
| `task_meeting` | встреча, где событие возникло |
| `closing_meeting` | встреча, где оно закрыто |

`task_event_id` — не только задачи: `ev_m002_03` — открытый вопрос «Кто делает интерфейс бота»,
его закрывает решение `ev_m009_01` (назначен Абдурахман). Остальные пять — задачи, закрытые отчётом о выполнении.

## Что в граф как связь не входило

В графе (`data/graph/`) закрытия не хранятся: связи между решениями — это `supersedes`, `contradicts`, `depends_on`,
`refines`, `same_topic`, а закрытие задачи или вопроса отдельным типом ребра не выражено. В `world.yaml` закрытия лежат
отдельным разделом `closures`, рядом со связями, но не среди них. Поэтому из `links.json` и `graph.json` этих пар
получить нельзя, а система должна находить их сама (задача «что остаётся открытым» — тип T5).

## Зачем

Оценка детекции закрытий (роль B): для каждой пары проверить, находит ли система закрывающее событие и связывает ли
его с исходной задачей или вопросом (полнота), и не выдаёт ли закрытий, которых здесь нет (точность). Задачи без
закрытия — документация API Squad (`ev_m003_03`, повторно `ev_m015_02`) и блок метрик продаж в Boost (`ev_m010_02`) —
в файл не попадают и должны остаться открытыми.

Файл лежит только в `data/gold/` и **не подаётся на вход системы** (извлечение, resolve, retrieval, UI): в нём ответы.
События `ev_m011_02`, `ev_m015_05` и другие из m_011–m_015 в `decisions.json` пока без цитат; сверка с цитатами для
них невозможна, пары даны по `world.yaml`.
