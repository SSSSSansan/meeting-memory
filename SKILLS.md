# SKILLS.md — повторяемые процедуры для Claude Code

Skill = короткий рецепт «как мы делаем X в этом проекте». Если задача подпадает под skill — следуй ему, не импровизируй. Любой skill заканчивается шагом **«запись в memory.md»**.

> Опционально: каждый skill можно вынести в `.claude/skills/<name>/SKILL.md`, тогда Claude Code подхватит их автоматически. Здесь — единый каталог.

---

## S0. memory-write — запись в `memory.md` (обязателен после любого значимого действия)

**Когда писать:** принято решение; найдена грабля; изменён контракт/порог/промпт; получена цифра метрики; получен ответ куратора; задача закрыта или заблокирована.
**Когда не писать:** тривиальные правки, то, что и так видно из `git log`.

**Формат записи** (добавлять в конец нужного раздела, новые сверху внутри раздела не вставлять):

```
- [YYYY-MM-DD][роль][ID задачи] Факт одной строкой. Почему: ... Влияет на: ...
```

**Разделы `memory.md`:** Статус · Решения · Контракты · Метрики · Грабли · Вопросы куратору · Данные.

**Правила:**
1. Сначала прочитай раздел — если такая запись есть, обнови её, а не дублируй.
2. Цифры метрик — с командой/конфигом, которыми получены (`backend`, `model`, `commit`).
3. Устаревшее не удаляй — помечай `~~...~~ (заменено YYYY-MM-DD)`.
4. Без секретов и реальных данных клиентов.
5. Коммит: `docs: update memory.md` (можно вместе с PR задачи).

## S1. add-transcript — добавить транскрипт

1. Формат — **Scribal raw JSON** (`text, language, detected_language, segments[start,end,speaker,text,words]`) в `data/raw/`, плюс мета-файл в формате `GET /meetings/{id}` (title, started_at, participants).
2. Прогнать `python -m src.ingest.scribal_adapter` → `data/transcripts/m_XXX.json`.
3. Проверить: `speaker` в маппинге, `ts` монотонны, нет пустых сегментов, NFC.
4. Для синтетики: заложить ситуацию из 7.1 (эволюция, кросс-проект, противоречие, забытое, написания, отмена, шум, смена языка) и описать в `data/gold/scenarios.md`.
5. Доля казахского по набору ≈ 25–30%; минимум 2 встречи преимущественно на казахском.
6. → S0.

## S2. run-extraction — извлечение и проверка

1. `python -m src.pipeline --stage extract --batch-size 5`
2. `python scripts/validate_extraction.py` — схема, цитаты-подстроки, проекты ∈ `projects_discussed`, нет дублей id.
3. Посмотреть hallucination rate и 5 случайных записей глазами.
4. Менять промпт → бампнуть `PROMPT_VERSION`, не затирая прошлые результаты (`runs/`).
5. → S0 (цифра hallucination rate + версия промпта).

## S3. update-contract — изменение контракта

См. `GIT.md` → «Изменение контракта». Только аддитивно. Обновить: `src/schemas.py`, `CLAUDE.md` (если касается Scribal/IO), тесты контрактов, `memory.md` → «Контракты».

## S4. add-eval-question — добавить вопрос в gold

1. Тип T1–T5, язык (`ru|mixed|kk`).
2. Эталонный ответ, `source_meetings` (список `meeting_id`), для T2/T4/T5 — ключевые решения (`decision_ids`).
3. Вопрос должен быть однозначно проверяем по gold; не придумывать то, чего нет в транскриптах.
4. Баланс: 10–12 на тип, ≥15% вопросов на казахском/смешанном.
5. → S0 при нетривиальном решении по разметке.

## S5. run-eval — прогон оценки

1. Бюджет: `python scripts/cost_guard.py --status`.
2. Отладка — `LLM_BACKEND=local`; финальные цифры — `openai`.
3. `python -m src.eval.run --mode both --repeats 3` → `results/*.csv|png`.
4. Разбивка: тип вопроса × режим, и срез по языку.
5. Провалы графа разобрать вручную (почему проиграл) — это материал для отчёта.
6. → S0 (таблица ключевых цифр + конфиг).

## S6. debug-llm-json — сломался structured output

1. Посмотри сырой ответ в `runs/*.jsonl`.
2. Retry с текстом ошибки валидации (максимум 2).
3. Локально — `guided_json` в vLLM; иначе fallback на openai для этой встречи (отметить в `memory.md`).
4. Не ослаблять схему, чтобы «проходило».

## S7. kazakh-check — проверка казахского

1. Эмбеддинги `bge-m3`: запрос на kk находит фрагмент на kk и на ru.
2. Extract на kk-транскрипте: цитаты проходят проверку подстроки (NFC!).
3. Resolve: «Айгерим / Аигерим / Айгерім» → один узел.
4. Ответ на вопрос на kk даётся на языке вопроса.
5. Срез метрик `ru / mixed / kk` обязателен в отчёте.

## S8. cost-report — стоимость

Собрать из `runs/*.jsonl`: токены индексации на встречу (по стадиям), токены/$ на вопрос по типам, задержка, обе ветки и оба backend. Итог — одна таблица в `results/` и в `REPORT.md`.
