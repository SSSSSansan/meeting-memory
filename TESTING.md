# TESTING.md — тесты и проверка качества

Два слоя: **код** (pytest, быстро, без сети) и **качество системы** (eval, платно/долго, по gold). Не путать.

## 2. Проверка данных (A)

- Каждый транскрипт проходит адаптер и `validate_extraction`-совместимую проверку: `ts` монотонны, нет пустых сегментов, NFC.
- Покрытие заложенных ситуаций: чек-лист 8 пунктов из 7.1 — у каждого есть встреча и таймкод в `scenarios.md`.
- Доля казахского по набору 25–30%, ≥2 встречи в основном на kk (скрипт подсчёта по `lang`/символам).
- Gold: 10% записей размечает второй человек; расхождения разбираются и фиксируются в `what_is_a_decision.md`.

## 3. Оценка качества системы (`python -m src.eval.run`)

| Группа | Метрика | Источник истины |
|---|---|---|
| Извлечение | P/R/F1 решений и задач | `gold/decisions.json`, совпадение по смыслу — судья + ручная выборка |
| Извлечение | hallucination rate | автоматически: цитата не подстрока |
| Resolve | accuracy кластеров | gold-кластеры проектов/людей |
| Связи | P/R по типу | `gold/links.json` |
| Ответы | accuracy | судья, калиброванный на 30 ручных примерах (указать согласованность) |
| Ответы | citation correctness | встречи в ответе == `source_meetings` |
| Ответы | hallucinated decisions | решения в ответе, которых нет в gold |
| Стоимость | токены/$/задержка | `runs/*.jsonl` |

Правила прогонов:
1. **3 повтора**, в таблице mean ± разброс.
2. Разбивка по типам **T1–T5** и по языку **ru / mixed / kk**.
3. Отладка — `LLM_BACKEND=local`; финальные цифры — `openai`; локальный вариант — отдельной таблицей на подмножестве.
4. Перед платным прогоном: `cost_guard --status`.
5. Фиксируем: commit, backend, модель, `PROMPT_VERSION`, глубину обхода графа, размер чанка — в заголовке результатов.
6. Ожидаемая гипотеза: T1 — паритет, T2/T3/T4/T5 — граф выигрывает. Если нет — это результат, не баг; разбор причин обязателен.

## 4. Smoke-тест перед сдачей (C)

Чистый клон → `pip install` → README-шаги → `python -m src.pipeline` на 5 встречах → `streamlit run` → один вопрос в каждом режиме → `pytest -q` зелёный → `ruff check .` чистый. Время ≤ 15 минут у человека, не участвовавшего в проекте.

## 5. Что считаем «готово» для PR

- `pytest -q` и `ruff check .` зелёные локально и в CI.
- Для задач с LLM — приложена цифра/пример прогона (одна строка в описании PR).
- Тесты затрагивают только свою зону; общие фикстуры — в `tests/fixtures/` через PR.
