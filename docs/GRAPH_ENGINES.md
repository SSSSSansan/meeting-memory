# NetworkX против Neo4j: что измерили (для разделов 6 и 7 отчёта)

Один и тот же граф встреч (14 встреч, 64 узла, 172 ребра) и четыре сценария, реализованные трижды: обходом в Python без индексов, обходом в Python со словарями-индексами и запросом на Cypher. Граф размножали непересекающимися копиями ×10, ×100, ×1000 (до 64 000 узлов и 172 000 рёбер). Результаты всех трёх реализаций совпали на всех сценариях и размерах. Сырые цифры: `results/graph_engines.json`, код: `scripts/neo4j/bench_engines.py`. Замер на Mac выполнила Panda, 2026-11-14, повторный (с индексом по типу и статусу) в тот же день; в таблице вторая версия, целиком.

## Как понят каждый сценарий

| сценарий | что именно считается | Cypher |
|---|---|---|
| S1 эволюция решения | все решения цепочки SUPERSEDES вокруг одного решения (`d_m001_01`), в обе стороны, любой длины | путь переменной длины `-[:SUPERSEDES*0..]-` |
| S2 кросс-проектный | в каких проектах человеку (`person:Николай`) что-то поручено: пары «проект\|пункт» по рёбрам ASSIGNED_TO и BELONGS_TO. Это не «связи между проектами» | соединение двух рёбер от пункта |
| S3 противоречия | все пары CONTRADICTS, **без фильтра по статусу решений** (не только «действующие») | один шаблон ребра |
| S4 открытые и просроченные | все задачи со статусом open; «просрочена», если срок раньше даты запроса (`2026-10-26`). Без проверки упоминаний на поздних встречах | фильтр по типу и статусу + CASE |

Запросы S1 и S2 всегда про копию 0, поэтому ответ не растёт; S3 и S4 собирают ответ по всем копиям, поэтому число строк растёт вместе с графом (столбец «строк в ответе»).

Что учитывать при чтении:
- **Neo4j идёт по сети.** Каждый запрос — обращение по bolt в Docker (новая сессия драйвера), минимум около 2–4 мс, а NetworkX работает в памяти. Поэтому на малых графах разница в сотни и тысячи раз в основном накладные расходы, а не работа с данными.
- **Индексы Neo4j:** `Node(nid)`, `Decision(project)`, `Node(type, status)`. Первый замер был без последнего: S4 на 64 000 узлов тогда занял 58 мс, с индексом — 61 мс. Индекс не помог, значит время S4 определяет не перебор узлов, а передача 4000 строк ответа по сети.
- **Холодный замер** (один первый запуск) есть в JSON. Настоящим холодным можно считать только ×1: у Neo4j там 55–360 мс против 4–7 мс прогретого. На ×10 и дальше сервер уже прогрет предыдущими размерами.
- **Индекс NetworkX** строится один раз (63 мс на 64 000 узлов, в таблице не учтён). Без индекса NetworkX перебирает узлы и рёбра.
- Считалась только медиана, среднее не считали.

## Стоимость входа

| | NetworkX | Neo4j |
|---|---|---|
| установка с нуля | `pip install networkx`, секунды | Docker + образ: 25.4 с на `docker compose up -d` (24.7 с скачивание) и ≈ 30 с ожидания готовности, плюс `pip install neo4j` |
| нужен интернет | только для установки | для скачивания образа |
| состояние в репозитории | да, `data/graph/graph.json` | нет, данные в томе Docker, граф грузится скриптом (в замере 11.2 с на ×1, куда входит создание индексов, и 9.8 с на ×1000) |
| построение в памяти | 0.1 мс на 64 узла, 0.5 с на 64 000 (индекс ещё 63 мс) | см. строку выше |

## Выводы строго по данным

- До 64 000 узлов NetworkX со словарями-индексами отвечает быстрее Neo4j во всех четырёх сценариях: от ×50 (S4 на 64 000 узлов) до ×5400 (S3 на 64 узлах).
- NetworkX без индексов тоже быстрее Neo4j почти везде. Единственная точка, где Neo4j оказался быстрее, — S3 на 64 000 узлов: 17 мс против 28 мс у NetworkX без индекса. С индексом NetworkX на том же размере отвечает за 0.08 мс.
- Точки, после которой Neo4j выигрывает у NetworkX с индексом, в измеренном диапазоне нет.
- На миллионах узлов не мерили, экстраполяций не делаем.
- Преимущества Neo4j не в скорости: хранение на диске, одновременный доступ нескольких пользователей, браузер для визуального разбора графа, граф больше памяти.

## Рекомендация для Scribal

Тысячи встреч дадут сотни тысяч узлов: это больше 64 000, которые мы мерили, но граф такого размера по-прежнему помещается в память одной машины. Поэтому переезд на Neo4j оправдан не скоростью, а многопользовательским доступом и хранением. Пока пользователь один и граф помещается в память, NetworkX проще и в наших замерах быстрее.

## Ограничения замера

- Граф синтетический, размножен копиями с той же структурой связей; реальные большие графы могут иметь другую форму.
- Neo4j в Docker на ноутбуке, сессия драйвера на каждый запрос; серверная конфигурация и пул соединений дали бы другие цифры.
- Python-реализации сценариев писались без оптимизации, кроме индексного варианта.
- Сценарии S2 и S3 упрощены относительно формулировки из плана («кросс-проектные связи», «действующие противоречия»): см. таблицу выше.

## SQLite, NetworkX, Neo4j: роль каждого

Это три разных хранилища, и они не конкуренты. Новых замеров здесь нет.

**NetworkX** — рабочий граф системы. Читается из `data/graph/graph.json`, лежит в памяти, из него отвечают все режимы поиска по графу. Хранится в репозитории и воспроизводится без Docker. Подходит, пока пользователь один и граф помещается в память.

**SQLite** (`src/store/`) — дополнительное реляционное хранилище, retrieval его не читает. Строится из `graph.json` и `data/raw` командой `python -m src.store.sqlite_store`. Хранит узлы, рёбра, встречи, реплики с таймкодом в секундах и таблицу алиасов. Те же запросы, что в `src/graph/queries.py` (решения проекта, цепочка замен, противоречия, открытые и просроченные задачи), плюс окно реплик вокруг секунды и поиск сущности по алиасу; тест проверяет, что результаты совпадают с версией на NetworkX. Удобен для фильтров по дате и проекту и для текстов с таймкодами; обход графа произвольной глубины в нём неудобен (цепочка замен делается рекурсивным запросом). Скорость SQLite не мерили.

**Neo4j** — граф как отдельный сервер. Нужен, когда понадобятся хранение на диске, одновременный доступ нескольких пользователей, визуальный разбор графа в браузере или граф больше памяти. В проекте используется только для замера (четыре сценария на Cypher), ответы пользователям из него не выдаются.

Векторный индекс (поиск по смыслу) в этот список не входит: это третье хранилище проекта, его сравнение не делали.
