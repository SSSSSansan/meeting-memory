# Meeting Memory (K02)

Память встреч для Scribal: из транскриптов встреч система извлекает решения, задачи и открытые вопросы,
связывает их между встречами и проектами и отвечает на вопросы руководителя со ссылками на встречу,
таймкод и дословную цитату.

Главный результат проекта — **честное сравнение архитектур на одних данных**:

- **baseline RAG** — поиск по фрагментам транскриптов, модель отвечает по найденному;
- **GraphRAG** — модель заранее извлекает решения и задачи, из них строится граф со связями
  «заменяет» и «противоречит», поиск идёт по графу;
- **hybrid** — граф поверх вектора: контекст графа плюс реплики вокруг его пунктов плюс обычный поиск.

Все ветки отвечают одним промптом и проходят одну проверку цитат, поэтому разница в качестве — от поиска,
а не от формулировок. Полный контекст задания, схемы и план — [`docs/K02_MEETING_MEMORY_CONTEXT.md`](docs/K02_MEETING_MEMORY_CONTEXT.md).

```
data/raw/*.json  (Scribal: transcript + meeting)
   │
   ├─► имена говорящих → чанки с заголовком метаданных → эмбеддинги → индекс ──► baseline ─┐
   │                                                                                      ├─► один промпт
   ├─► извлечение (LLM) → resolve → связи (LLM) → граф NetworkX ─────────────► graph ─────┤   → проверка цитат
   │                                                                                      │   → ответ
   └─────────────── граф + реплики вокруг его пунктов + поиск по индексу ──► hybrid ──────┘   (auto выбирает
                                                                                              baseline/graph)
eval (роль A): одни вопросы во всех режимах → results/eval_<run_id>.json → вкладка «Метрики»
```

## Запуск демо с чистого клона (около 10 минут)

Нужны Python 3.11+ и git. Ключи не нужны: по умолчанию `LLM_BACKEND=stub`, всё работает без модели и денег,
но ответы и поиск по смыслу случайны — так проверяется сам интерфейс.

```bash
git clone https://github.com/SSSSSansan/meeting-memory.git
cd meeting-memory
python -m venv .venv
```

```bash
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt    # 3–8 минут: streamlit тянет много пакетов
cp .env.example .env               # Windows: copy .env.example .env
streamlit run app/streamlit_app.py
```

Откроется http://localhost:8501. Что показать:

1. **Боковая панель → «Загрузить демо-встречи».** Индексируются 14 синтетических встреч из `data/raw/` батчами по 5.
   Ниже — какой граф читать; по умолчанию полный граф по тем же 14 встречам.
2. **«Вопросы».** Режимы `baseline`, `graph`, `hybrid`; `auto` сам выбирает ветку и пишет почему; `сравнить` —
   три режима рядом на один вопрос. У каждой цитаты — «Показать в транскрипте» с подсветкой. Под ответом graph и
   hybrid — «Из графа в контекст»: рисунок пунктов, которые реально ушли модели. Внизу токены, стоимость и время.
3. **«Таймлайн проекта».** Решения и задачи проекта по дате: заменённые зачёркнуты, конфликты красные.
4. **«Граф».** Рисунок проекта: связи «заменяет», «уточняет», «конфликт». После вопроса — подсветка подграфа
   последнего ответа: жирная рамка у того, что ушло в контекст, остальное приглушено.
5. **«Конфликты и замены».** Например, Николай в одни даты поставлен и на Squad (m_007), и на хотфикс Zhol (m_008).
6. **«Метрики».** Итоговая таблица прогона eval: режимы × типы вопросов T1–T5, среднее с 95% интервалом,
   разность graph − baseline с выводом, источники и полнота поиска, стоимость и задержка. Пока настоящего прогона нет,
   показывается фикстура роли A с жёлтой пометкой «числа выдуманы».

Вопросы для показа и ожидаемые ответы — [`data/gold/scenarios.md`](data/gold/scenarios.md) и `data/gold/questions.json`.

### С настоящей моделью

В `.env`: `LLM_BACKEND=openai`, `OPENAI_API_KEY=…`, модели и **актуальные цены** (`PRICE_IN_PER_M`,
`PRICE_OUT_PER_M`, `PRICE_EMBED_PER_M`) — по ним `cost_guard` считает траты и останавливает всё при `BUDGET_USD`.
Один вопрос на gpt-4o-mini стоит доли цента. Сколько уже потрачено: `python -m scripts.cost_guard --status`.

Индекс хранит, какой моделью эмбеддингов и в каком формате чанков он собран, и чужой не загрузит. После смены
модели или обновления кода с новым форматом чанков нажмите «Очистить индекс» и снова «Загрузить демо-встречи»
(14 встреч ≈ 750 чанков, на `text-embedding-3-small` — около цента).

Переменные окружения сильнее `.env`: `LLM_BACKEND=stub streamlit run app/streamlit_app.py` запускает интерфейс
без трат, даже если в `.env` стоит `openai`.

## Как ищет каждый режим

**baseline** ([`src/retrieval/baseline.py`](src/retrieval/baseline.py)). Чанк — окно из 3 реплик со сдвигом 2.
Эмбеддится вместе с заголовком `[m_007 | 2026-08-31 | «Squad: планирование» | проекты: Squad, Qamqor | говорящие | ts]`:
в реплике «давайте перенесём на двадцатое» нет ни проекта, ни даты, и без заголовка вопрос про проект её не найдёт.
Проекты встречи берутся из названия и из текста (от двух упоминаний; Жол / Zhol / Джол склеиваются). Поиск:
жёсткий фильтр только по дате встречи ≤ `as_of` → 40 кандидатов по косинусу → мягкий буст за проект и свежесть →
без почти-дублей → 10 в контекст. По проекту жёстко не фильтруем: встреча «Zhol» может обсуждать Qamqor.

**graph** ([`src/retrieval/graph_rag.py`](src/retrieval/graph_rag.py)). Проекты и люди из вопроса (с вариантами
написания) → обход на глубину 2 → пункты с хронологией, статусами (действует / заменено, открыта / выполнена) и связями.
Если пунктов больше 10, остаются важнейшие: ближе к сущностям вопроса, в конфликте, действующие, свежие; цепочка
замен решения берётся целиком — иначе из ответа «как менялся срок» выпадет середина.

**hybrid** ([`src/retrieval/hybrid.py`](src/retrieval/hybrid.py)). До 4 первых пунктов того же ранжирования graph +
к ним до 3 чанков транскрипта в пределах 45 секунд от таймкода пункта (ближайшие к вопросу) + обычный поиск до 10
элементов всего. Граф знает только то, что поймал экстракт; реплики рядом добирают пропущенное. Один фрагмент,
найденный двумя путями, занимает одно место.

**Один бюджет контекста.** Каждый режим отдаёт модели не больше `CONTEXT_K = 10` элементов (чанк транскрипта или
пункт графа), иначе граф выигрывал бы объёмом, а не устройством. Токены у элементов разные — их eval считает
отдельно (`context_tokens`). Контроль `longctx` (все встречи целиком) бюджетом намеренно не ограничен.

У каждого ответа есть `retrieved_meetings` — встречи, попавшие в контекст до генерации: по ним eval отделяет
«поиск не нашёл» от «модель не использовала».

## Полный конвейер и eval

Готовые результаты лежат в репозитории, поэтому для демо ничего пересобирать не нужно. Шаги ниже вызывают
модель и **стоят денег** (кроме проверок и `--dry-run`); перед платным запуском — `cost_guard --status`.

```bash
python -m src.extract.run --raw --out data/extracted_llm_raw             # B: извлечение по data/raw
python -m scripts.validate_extraction data/extracted_llm_raw --raw       # B: схема, дословность цитат, hallucination rate
python scripts/compare_gold.py data/extracted_llm_raw                    # B: сверка с эталоном
python -m src.graph.link                                                 # B: связи решений → data/graph/links.json
python scripts/build_graph.py --links data/graph/links.json              # B: граф → data/graph_raw/graph.json
python -m src.eval.run --mode both --split dev --as-of m_015 --judge-facts --dry-run        # A: план и цена, без вызовов
python -m src.eval.run --mode both --split dev --as-of m_015 --judge-facts --confirm-paid   # A: прогон
```

Eval держит «что известно на дату вопроса» (`as_of`): система видит только встречи до неё. Качество ответа —
F1 по фактам (судья отмечает, есть ли в ответе каждый эталонный факт, и что ответ утверждает сверх них), рядом
считаются арифметикой полнота и точность по встречам-источникам и полнота поиска. Интервалы — парный бутстрап по
вопросам: одни и те же вопросы во всех режимах. Вопросы разделены на dev (настраиваем) и test (запускается один раз).
Прогон пишет `results/eval_<run_id>.json` — его без пересчёта показывает вкладка «Метрики»; после сбоя прогон
продолжается с `--resume --run-id <тот же>`. Подробности — в docstring [`src/eval/results_v2.py`](src/eval/results_v2.py).

Отдельные инструменты для отладки:

```bash
python -m src.answer.answerer "Как менялся срок релиза Zhol?" --mode hybrid --as-of 2026-09-30
python -m src.retrieval.graph_rag "Что по Камкор ещё не закрыто?" --depth 2
python -m src.retrieval.baseline "Кто делает миграцию?" --as-of 2026-09-30
```

## NetworkX и Neo4j

Ответы на вопросы строит граф в памяти на NetworkX:

- **Объём.** 14 встреч — это десятки решений и задач и пара сотен рёбер. Обход такого графа в памяти занимает
  миллисекунды.
- **Ноль инфраструктуры.** NetworkX — библиотека: граф поднимается одним `pip install`, без сервера, пользователей
  и портов, проверяющий воспроизводит результат без Docker.
- **Граф — файл в репозитории.** `graph.json` (`networkx.node_link_data`) коммитится, его видно в PR и можно сравнить
  между прогонами.

Сравнение с Neo4j делается замером, а не мнением (роль B, план B7/B10): те же четыре сценария (эволюция решения,
кросс-проектные связи, действующие противоречия, открытые пункты) на NetworkX и на Cypher — совпадение результатов,
скорость, стоимость входа, объём кода и рост времени на графе, размноженном в 10, 100 и 1000 раз. Цифры и порог,
с которого Neo4j оправдан, — в `REPORT.md` (пишет роль A) после замера. Код читает граф только через
`src/graph/queries.py` и `src/retrieval/graph_rag.py`, поэтому смена хранилища затронет их, а не UI и eval.
Фреймворки оркестрации (LangChain, LangGraph) не используются: конвейер линейный, а нам нужен точный контроль
над промптами и подсчётом токенов.

## Роли и вклад

| Роль | Кто | Зона |
|---|---|---|
| A. Данные и оценка | _имя_ | `data/raw`, `data/noisy`, `data/gold`, `src/eval`, скрипты данных и судьи, `REPORT.md` |
| B. Извлечение и граф | Saniya | `src/extract`, `src/resolve`, `src/graph`, `src/ingest`, `scripts/build_graph.py`, `scripts/validate_extraction.py` |
| C. Поиск, ответы, приложение | _имя_ | `src/retrieval`, `src/answer`, `app`, `src/api.py`, `src/llm_client.py`, `scripts/cost_guard.py`, CI, README |

Общий контракт — `src/schemas.py`, меняется только добавлением полей и по согласованию всех. Статус каждой задачи —
[`TEAM.md`](TEAM.md), решения и известные проблемы — [`memory.md`](memory.md).

**A — данные и оценка.** Сюжет на 4 проекта и 7 человек с заложенными ситуациями (`world.yaml`): перенос срока,
замена и отмена решения, конфликт загрузки, забытая задача, смешанная речь. 14 встреч в формате Scribal и слой шума ASR.
Эталон решений и задач с цитатами, закрытия задач, 58 вопросов T1–T5 с разделением на dev и test. Eval с `as_of`,
F1 по фактам, полнотой поиска, парным бутстрапом, срезами по типам и языку; LLM-судья и калибровка по ручной разметке.

**B — извлечение и граф.** Адаптер Scribal, восстановление имён говорящих, единая нормализация текста для
казахских букв. Извлечение с проверкой дословности цитат и повтором: **0 % выдуманных цитат на всех
14 встречах** (m_001–m_013, m_015; m_014 нет), найдено 29 из 30 событий эталона (gpt-4o); decision
precision 0.86 / recall 0.95, task 0.88 / 0.88, open_question 1.00 / 1.00. Склейка вариантов имён и
проектов. Связи решений: 8 в графе, все проверены по цитатам и подтверждены черновиком сюжета
(`world.yaml`), precision 1.00 / recall 0.89 против черновика. Сборка графа по всем 14 встречам (22
решения, 10 задач, 3 вопроса) с вычисляемыми статусами `active/superseded` и отдельный срез без утечки
будущего для эталона A (`as_of=m_008`).

**C — поиск, ответы, приложение.**
- Baseline: окна реплик с перекрытием и заголовком метаданных (встреча, дата, проекты всей встречи, говорящие),
  имена говорящих как в графе, фильтр по `as_of`, широкий пул с пересортировкой и без почти-дублей.
- Hybrid: граф + реплики вокруг его пунктов + поиск, без повторов.
- Ответ в едином формате для всех веток; каждая цитата проверяется на дословность, при ошибке — один повтор
  с перечнем плохих цитат, неподтверждённые удаляются с пометкой; `retrieved_meetings` для полноты поиска.
- GraphRAG: проекты и люди из вопроса (с вариантами написания через resolve B) → обход графа → контекст
  с хронологией, статусами и связями.
- Роутер `auto` по признакам T1–T5 на русском и казахском, без LLM.
- Streamlit: загрузка, три режима и сравнение, источники с подсветкой, подграф контекста, таймлайн, рисунок графа,
  конфликты и замены, вкладка метрик по результату eval.
- LLM-клиент с кэшем, бюджетом и логом токенов, стоимости и задержки; CI.

## LLM backend и настройки

Весь код ходит в модель только через `src/llm_client.py`; ключи — только в `.env` (он в `.gitignore`).
Переменная, уже заданная в окружении, сильнее строки в `.env`.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `LLM_BACKEND` | `stub` | `stub` — без модели и денег; `openai`; `local` — OpenAI-совместимый сервер (vLLM, Ollama) |
| `LLM_MODEL`, `EMBED_MODEL` | `gpt-4o-mini`, `text-embedding-3-small` | модели ответа и эмбеддингов |
| `OPENAI_API_KEY` | — | ключ для `openai` |
| `LOCAL_BASE_URL`, `LOCAL_API_KEY` | `http://localhost:8000/v1` | адрес локального сервера |
| `PRICE_IN_PER_M`, `PRICE_OUT_PER_M`, `PRICE_EMBED_PER_M` | `0` | цены за 1M токенов; без них учёт трат показывает ноль |
| `JUDGE_MODEL`, `JUDGE_PRICE_IN_PER_M`, `JUDGE_PRICE_OUT_PER_M` | как у `LLM_MODEL` | модель и цены LLM-судьи в eval |
| `BUDGET_USD` | `3.0` | жёсткий лимит: при превышении вызовы падают с `BudgetExceeded` |
| `LLM_MAX_RETRIES`, `LLM_TIMEOUT_S` | `3`, `120` | повторы при сбоях сети, 429 и 5xx |
| `MEETING_GRAPH` | — | какой граф читают graph и hybrid; без неё — первый из `data/graph/graph.json`, `data/graph_raw/graph.json`, `data/sample/graph.json`. В UI граф выбирается в боковой панели |

Логи: каждый вызов модели и эмбеддингов — `runs/calls.jsonl` (`purpose`, токены, `cost_usd`, `spent_usd`, задержка;
у ответов из кэша `spent_usd = 0`); каждый вопрос — `runs/answer_report.jsonl` (режим, маршрут `auto`, `as_of`,
`retrieved_meetings`, у hybrid — `context_parts`, цитаты до и после проверки, токены, `latency_ms`, `retrieval_ms`,
`llm_ms`, `from_cache`).

## Интерфейсы для интеграции

UI и eval ходят только в `src/api.py`; логики в `app/` нет.

```python
from src import api

pairs, errors = api.pair_scribal_files({"m_001.transcript.json": b"...", "m_001.meeting.json": b"..."})
transcripts = [api.load_scribal(*p) for p in pairs]       # Scribal raw + meta → Transcript, с именами говорящих
for done, total in api.index_batches(transcripts): ...    # батчи по 5, индекс сохраняется после каждого
api.ask("Как менялся срок релиза Zhol?", mode="hybrid", as_of="2026-09-30")   # → src.schemas.Answer
api.route("Что по Qamqor ещё не закрыто?")                # какую ветку выберет auto и почему
api.context_subgraph("Как менялся срок релиза Zhol?")     # пункты графа, которые уйдут в контекст
api.get_timeline("Жол")                                   # пункты проекта по времени: статус, связи, цитата
api.get_changes()                                          # конфликты и замены решений
api.get_source("m_006", "00:06:02", "релиз Zhol переносится")  # реплика с цитатой и соседние, подсветка
api.available_graphs(); api.use_graph(path)                # выбор графа для graph, таймлайна и рисунка
api.eval_runs(); api.quality_table(api.load_eval(path))    # прогоны eval и таблицы для вкладки «Метрики»
```

## Ограничения

- **Данные синтетические.** Реальных транскриптов клиентов нет; синтетика написана с шумом ASR, смешанной речью
  и заложенными ловушками, но качество на живых встречах будет ниже.
- **Цифры сравнения режимов появятся после платного прогона eval**; до него вкладка «Метрики» показывает фикстуру
  с пометкой. На `stub` ответы и поиск по смыслу случайны.
- **Вопросов немного:** на test по несколько вопросов каждого типа, поэтому утверждения по отдельным типам делаются
  на dev и помечаются как разведочные.
- **Эмбеддинги — OpenAI `text-embedding-3-small`.** Локальная модель (vLLM, `bge-m3`) не развёрнута; выбор эмбеддера
  — замером полноты поиска (роль A), поиск между казахскими и русскими фрагментами на `stub` не проверяется.
- **Имена говорящих** восстанавливаются эвристикой: она не ошибается на эталоне, но называет только около
  пятой части реплик; остальные остаются `SPEAKER_XX` — одинаково в графе и в индексе.
- **Граф знает только то, что поймал экстракт.** Hybrid закрывает это репликами рядом с пунктами графа и обычным
  поиском; обход графа роли B (B6) ещё заменит графовую часть.
- **Пакетного конвейера одной командой нет** (`src.pipeline` из плана): шаги запускаются по отдельности, см. «Полный конвейер».
- **Роутер `auto` — правила по словам вопроса**; hybrid он не выбирает, этот режим включается явно.
- **UI рассчитан на одного пользователя**: выбор графа общий для процесса Streamlit.
